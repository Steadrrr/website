## 1. 이름 (제안 — 확인 필요)
**「쉬자ON」 — 휴양시설 현장업무 원스톱 플랫폼**
- 한 줄: *종이·엑셀·단톡방에 흩어진 현장업무를 한곳에 기록하고, 쌓인 데이터로 AI가 민원·고장을 미리 알려준다.*
- 다른 후보: 「숲 운영노트 AI」, 「쉬자파크 스마트운영」

## 2. 기능 재구성 — 누더기 → 5+1 묶음
| 묶음 | 지금 기능 (현재 메뉴 위치) | 한 줄 메시지 |
|---|---|---|
| ① 기록·결재 | 업무일지·매출보고(운영관리), 결재함·문서관리(개인업무), 공지·일정 | 현장 기록이 곧 보고서 |
| ② 객실 운영 | 객실판매관리, 청소관리 앱(PWA·푸시), 객실운영관리, 소모품, AR사용 | 퇴실→청소→입실가능 실시간 공유 |
| ③ 재정·상품권 | 상품권관리(금고·불출/반납·수불부·서명·대조), 매출, 할인·환급 자동계산 | 계산은 시스템이, 사람은 확인만 |
| ④ 시설·안전 | 시설점검, 시설물, 장비(이력·비용), 물품구매 | 언제·어디를·얼마 들여 고쳤는지 이력 |
| ⑤ 고객·프로그램 | 민원관리(3단계 분류), 유실물, 프로그램(산림치유·유아숲·숲해설) | 민원을 '분류된 데이터'로 쌓는다 |
| ＋ AI 예측 (신규) | ④+⑤ 데이터 → Claude | "다음 주에 생길 일"을 미리 |
- 근태·통계·조직도는 각 묶음 안으로 넣거나 '관리' 묶음으로.
- 전체 흐름(설명의 뼈대): `기록(현장) → 공유(실시간) → 확인(결재) → 축적(데이터) → 예측(AI)`
- 메뉴 재구성은 **이름·순서만** 바꾸고 기능은 건드리지 않는다 (운영 사이트 반영 여부는 별도 결정).

## 3. 효과 · 기대 결과
- 정량 (측정 필요): 일지 작성·결재 시간, 상품권 대조·수불부 작성 시간, 청소완료 전달 지연(무전·전화 → 푸시), 환급 계산 오류 건수.
  → 운영 DB에서 사용 실적(일지 수·민원 건수·청소 처리 건수 등) 추출 + 실무자 2~3명 도입 전/후 체감 시간 설문.
- 정성: 종이 없는 운영, 인수인계 누락 방지, 권한별 접근으로 책임 명확, 개인정보 최소 보관(엑셀 업로드 후 즉시 삭제).
- 확산성: 군내 다른 휴양림·캠핑장·체육시설 운영부서에 그대로 적용 가능 (전문가 심사 포인트).

## 4. AI 예측 설계 — 민원 · 시설물 보수
**원칙: 숫자 계산은 PHP(통계), 해석·요약·권고는 Claude.** LLM이 확률을 지어내지 않게 하고 근거를 함께 보여 준다.

### 민원 예측
- 입력: `complaints`(cat1~3, channel, place_type/place_id, work_date, status, done_date) + 객실 예약률(일일객실판매) + 요일·계절·성수기(seasons)
- 출력: "다음 주 예상 민원 Top 5 + 사전 조치 체크리스트" (예: 주말 4인실 만실 → 온수·난방 문의 증가 → 금요일 보일러 점검)
- 보너스: 민원 내용 입력 시 Claude 가 분류(대/중/소) 자동 제안 → 입력 부담↓ 데이터 품질↑

### 시설물 보수 예측
- 입력: 시설점검 `facility_items`(result, note) + `equipment_logs`(inspect/repair, cost, vendor) + `equipment.acquired_on`(내용연수) + 시설 관련 민원
- 출력: 시설별 위험 점수 + 근거 + 보수 우선순위 + 예산 추정

## 5. 데이터 관리 점검 (실제 테이블 확인 결과)
| 항목 | 현재 | 보완 |
|---|---|---|
| 민원 분류 | ✅ 3단계 코드·장소·처리상태·완료일 있음 | 그대로 활용 (가장 준비된 데이터) |
| 시설점검 결과 | ⚠️ `facility_items.result` 자유 문자열(config `facility_results`: 정상/점검필요/수리요청/조치완료), `facility_id` NULL(직접입력) 허용 | 결과 코드 고정, 등록 시설 선택 유도 |
| 장소 연결 | ⚠️ 민원 장소 ↔ 시설물(facilities) ↔ 장비(equipment.location 자유문자) 연결 약함 | 같은 위치 ID 로 묶어 "이 시설의 민원+고장 이력" 합치기 |
| 데이터 양 | ⚠️ 운영 기간 짧음 | 과거 엑셀·종이 민원·수리 기록 일괄 등록, 없으면 "쓸수록 정확해지는 구조"로 설명 |
| 개인정보 | ⚠️ 민원 본문에 이름·전화번호 섞일 수 있음 | API 전송 전 자동 마스킹, 통계·익명 텍스트만 전송 |
| AI 결과 | 없음 | `ai_insights` 테이블에 예측 저장 → 실제와 비교해 적중률 제시 |
- Claude API 키는 서버 설정(settings 또는 config.php)에만. 코드·채팅·커밋 금지. 주 1회 예측 + 분류 제안 수준이면 비용 미미.
