| 묶음 | 지금 기능 (현재 메뉴 위치) | 한 줄 메시지 |
|---|---|---|
| ① 기록·결재 | 업무일지·매출보고(운영관리), 결재함·문서관리(개인업무), 공지·일정 | 현장 기록이 곧 보고서 |
| ② 객실 운영 | 객실판매관리, 청소관리 앱(PWA·푸시), 객실운영관리, 소모품, AR사용 | 퇴실→청소→입실가능 실시간 공유 |
| ③ 재정·상품권 | 상품권관리(금고·불출/반납·수불부·서명·대조), 매출, 할인·환급 자동계산 | 계산은 시스템이, 사람은 확인만 |

- 메뉴 재구성은 **이름·순서만** 바꾸고 기능은 건드리지 않는다 (운영 사이트 반영 여부는 별도 결정).

## 4. AI 예측 설계 — 민원 · 시설물 보수
**원칙: 숫자 계산은 PHP(통계), 해석·요약·권고는 Claude.** LLM이 확률을 지어내지 않게 하고 근거를 함께 보여 준다.

### 민원 예측
- 입력: `complaints`(cat1~3, channel, place_type/place_id, work_date, status, done_date) + 객실 예약률(일일객실판매) + 요일·계절·성수기(seasons)
- 출력: "다음 주 예상 민원 Top 5 + 사전 조치 체크리스트" (예: 주말 4인실 만실 → 온수·난방 문의 증가 → 금요일 보일러 점검)
- 보너스: 민원 내용 입력 시 Claude 가 분류(대/중/소) 자동 제안 → 입력 부담↓ 데이터 품질↑

### 객실 소모품 구매 예측 (사용자 제안 2026-10-22)
- 입력: 물품구매 문서(품목·수량·단가·날짜) + 소모품관리 재고(입고·출고) + 판매 객실 수(박) + 다음 4~8주 예약률·작년 같은 기간
- 숫자(PHP): 품목별 '객실 1박당 사용량', 현재 재고 ÷ 예상 사용량 = 남은 기간, 지난 구매 간격, 단가 변화
- 출력(Claude): "언제·무엇을·얼마나 사야 하나" 구매 목록 초안 + 예상 금액 (근거: 지난 구매일·사용 속도), 물품구매 문서 초안으로 바로 넘기기
- 실제 근거(2025~26 견적서 8건, 객실 품목만): 세제·화장지는 성수기 전(4·7월)과 동절기 전(11월)에 묶음 구매, 연초(1월) 비품 교체.
  세탁세제 단가 27,500 → 33,600원(+22%). 민원·만족도의 불편이 다음 구매로 이어짐(배수 → 배수 세정제, 현관문 말발굽 → 도어스토퍼 19개, 벽시계 요청 → 벽시계, 프라이팬·집게)

### 시설물 보수 예측
- 입력: 시설점검 `facility_items`(result, note) + `equipment_logs`(inspect/repair, cost, vendor) + `equipment.acquired_on`(내용연수) + 시설 관련 민원
- 출력: 시설별 위험 점수 + 근거 + 보수 우선순위 + 예산 추정

## 5. 데이터 관리 점검 (실제 테이블 확인 결과)
| 항목 | 현재 | 보완 |
|---|---|---|
| 민원 분류 | ✅ 3단계 코드·장소·처리상태·완료일 있음 | 그대로 활용 (가장 준비된 데이터) |
| 시설점검 결과 | ⚠️ `facility_items.result` 자유 문자열(config `facility_results`: 정상/점검필요/수리요청/조치완료), `facility_id` NULL(직접입력) 허용 | 결과 코드 고정, 등록 시설 선택 유도 |
| 장소 연결 | ⚠️ 민원 장소 ↔ 시설물(facilities) ↔ 장비(equipment.location 자유문자) 연결 약함 | 같은 위치 ID 로 묶어 "이 시설의 민원+고장 이력" 합치기 |
| 데이터 양 | ⚠️ 운영 기간 짧음 | 과거 엑셀·종이 민원·수리 기록 일괄 등록, 없으면 "쓸수록 정확해지는 구조"로 설명 |
| 개인정보 | ⚠️ 민원 본문에 이름·전화번호 섞일 수 있음 | API 전송 전 자동 마스킹, 통계·익명 텍스트만 전송 |
| AI 결과 | 없음 | `ai_insights` 테이블에 예측 저장 → 실제와 비교해 적중률 제시 |
- Claude API 키는 서버 설정(settings 또는 config.php)에만. 코드·채팅·커밋 금지. 주 1회 예측 + 분류 제안 수준이면 비용 미미.

**추가 제안**
1. **객실 QR 하나로** — 객실에 QR 한 장: 이용 안내·와이파이·챗봇·물품 요청·고장 신고(사진)·퇴실·만족도. 앱 설치 없이 웹으로 (1단계는 도어락 없이도 가능)
2. **고객 고장 신고 → 장비 이력 자동 연결** — 사진과 함께 들어온 신고가 그 객실 설비 이력에 바로 붙어 AI 예측의 재료가 된다
3. **온수보일러 차단기 감시(소형 IoT 센서·스마트 차단기)** — 가장 많이 반복된 고장(히터봉·차단기 트립 14건)을 고객 민원 전에 알림
4. **도어락 출입 기록 활용** — 첫 출입 = 실제 입실(노쇼 확인), 퇴실 처리와 함께 청소 순서 자동 배정

추가 제안 1~4 모두 채택 (사용자 2026-10-22).

**운영 방식 결정 (사용자 2026-10-22)**
- **지역상품권**: 입실 전에 객실에 비치하고 사진으로 확인 (비치한 직원 + 입실한 고객 모두 사진 확인) → 지급 기록이 사진과 함께 남는다
- **할인 자격**: 미리 증빙을 받아 오거나, 입실 전에 운영사무실을 따로 방문해 확인
- **예약 정보**: 지금은 예약 엑셀에서 입실인원·할인여부만 읽고 파일은 바로 지운다. 스마트 체크인 때는 **휴대폰 번호·차량번호만** 추가로 쓰고, 처리 후 바로 지운다
- **대리예약 방지 안전장치**는 필요 — 방법은 나중에 정한다 (이번 범위 아님)
- **예약 출처**: 전국 국공립 휴양림 통합예약 '숲나들이'(foresttrip.go.kr)의 관리자 페이지 → 예약 내역을 받아(현재처럼 엑셀 내려받기 등) 비밀번호 발송·차량 등록에 쓰고 바로 삭제.
  자동 연동(API)이 되는지는 운영기관 확인 필요 — 안 되면 엑셀 업로드 방식으로 시작
- 장비 비용(도어락 19개·차단기 연동·알림톡)은 업체 견적 필요

**향후 단계(구상)**
1. 비용 거의 없음: 객실 QR 웹(안내·요청·고장 신고·웹 퇴실·만족도) → 청소관리·민원·장비 이력과 연결
2. 챗봇(Claude): 안내 문의 응답 + 요청 자동분류·접수, 긴급 건 당직 연결
3. 예산 필요: 스마트 도어락 OTP + 알림톡 발송, 차량번호 → 차단기 연동(LPR 확인 후), 보일러 차단기 IoT
