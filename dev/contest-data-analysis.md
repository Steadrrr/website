## 1. 문제 (Before) — 기록은 많은데 흩어져 있고 끊긴다
- **같은 고장이 4곳에 따로 적힌다.** 예: 숲B 온수 고장(2026.6)
  - 단톡방: 6/15·6/20 보고, 민원 관리대장: 6/15·6/20 두 줄, 만족도 조사: 6/14 "온수 온도 문제로 다른 객실에서 샤워",
    **시설물 관리대장: 2026.2 히터봉 교체 한 줄뿐** (6월 재발은 없음)
- **단톡방이 사실상 시설 대장이다.** 9개월 메시지 3,751개(하루 평균 13개, 근무시간 밖 19%), 그중 고장·누수·펌프·보일러·벌집 등
  시설 관련이 약 345개. 시설물 관리대장에 남은 2026년 이력은 **1건**.
- **대장이 중간에 끊긴다.**
  - 객실 민원 관리대장: 3·4월, 9·10월 비어 있음. 47건 중 처리일자 없음 34건(72%), 처리여부 없음 26건(55%)
  - 전화 응대 현황: 691줄 중 분류 칸 비어 있음 423줄(61%) → 월별·분야별 통계를 낼 수 없음
  - 시설 보수 대장(2024~25): 104건 중 조치일자 없음 57건(55%), 조치일이 발생일보다 앞선 오기 3건
  - 시설물 관리대장 보수 이력 40건 중 날짜 없는 이력 11건
- **분류가 제각각이다.** 민원 대장은 청소/시설/고객응대 3가지, 전화 현황은 12가지(공원시설·숙박전체…), 보수 대장은 시설/장비 + 자유 입력.
  같은 장소도 '치유의집/치유센터', '관정/제설기(시설)'처럼 섞여 표기됨.

## 2-1. 객실 소모품·비품 구매 (견적서 8건, 객실 관리 품목만)
- 제외한 것(객실 관리와 무관): 파일철, 응모함·룰렛, 테이블보, 경광등, 라바콘, 페인트, 바닥 왁스, 고압세척기 노즐, 작업 발판
- 2025년 객실 관련 약 543만 원 / 2026년(10월까지) 약 418만 원. 구매는 **1월(비품 교체), 4·7월(성수기 전), 10·11월(동절기 전)**에 몰린다
- 반복 소모품: 세탁세제·섬유유연제 14L(4월 6·5통 → 11월 7·3통 → 26년 7월 6·5통), 화장지 100롤(5박스 → 10박스), 점보롤, 락스, 쓰레기봉투, 행주, 장갑
- 단가 상승: 세탁세제 27,500 → 33,600원(+22%), 섬유유연제 27,500 → 29,700원
- **민원이 구매로 이어진다**: 배수 불만(8건) → 배관 세척제·배수구 세정제(26.7·26.10), 현관문 말발굽 파손 → 도어스토퍼 19개(26.10), 벽시계 비치 요청 → 벽시계(26.7),
  벌레(8건) → 파리채 19개·모기약, 냄새 → 방향제·욕실 환풍기, 프라이팬 코팅·집게 불만 → 프라이팬·집게(25.4) 교체 주기 약 1년
- 예측으로 바꾸면: "객실 1박당 사용량 × 다음 기간 예약 → 품목별 재고 바닥 시점 → 구매 목록 초안·예상 금액"

## 3. 시스템에 반영한 것 / 할 것
- **체험판 가상 자료** (`app/demo_seed.php`): 객실 19개·시설 구역·위 표의 고장 이력(날짜 간격 그대로, 업체명 일반화)·월별 문의량·계절 민원을 본떠 만듦.
  구매 견적서 8건의 객실 품목은 물품구매 문서(결재·지출완료) + 소모품관리 재고(구매 입고, 판매 객실 수에 비례한 주간 출고)로 넣음.
- **분류 통일**: 민원 3단계 분류(CPL_TREE)가 민원대장 3분류 + 전화현황 12분류를 모두 담는다 (대응표는 AI 자동분류 시험에 사용).
- **AI 예측 설계 보완** (contest-plan 4절):
  1. 숫자(PHP): 설비별 마지막 고장·교체일, 같은 설비 반복 횟수, 작년 같은 달 민원·고장 건수, 다음 4주 예약률
  2. 해석(Claude): 위 숫자 + 계절 → "다음 4주에 일어날 일 Top 5 + 근거 + 미리 할 일" (확률을 지어내지 않고 근거 건수를 함께 표시)
  3. 검증: 2025년 기록만 주고 2026년 상반기를 예측시켜 실제와 비교 (설명서의 '적중' 사례)
- **AI 자동분류 시험셋**: 민원대장 47 + 전화현황 691 + 만족도 불편 48 문장 (원본에서 개인정보 제거 후 로컬에서만 사용).
